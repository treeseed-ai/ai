# TreeSeed AI 0.6.1

TreeSeed AI 0.6.1 adds the explicit takeover path for a running 0.4 local
factory. The migration is deliberately operator-approved: installing the new
central package does not stop the old coordinator or change product state.

Run the non-mutating plan first, then authorize the handoff:

```bash
sudo /usr/lib/treeseed-ai/bootstrap/migrate-0.4.sh plan
sudo /usr/lib/treeseed-ai/bootstrap/migrate-0.4.sh apply --confirm
sudo journalctl -fu treeseed-ai-bootstrap.service
```

The plan blocks while inference or GPU training work is active and when the
existing product credentials, factory TLS identity, signing identity, or GPU
mode cannot be preserved. The bootstrap records a hashed recovery snapshot,
stops the old coordinator immediately before package installation, and hands
the same Compose projects, volumes, environments, certificates, signing keys,
and awake/sleep mode to the manager.

The first migrated convergence uses registry images and the stable channel with
automatic updates paused. After checking `treeai platform doctor` and
`treeai update status`, an operator can explicitly select an update policy or a
development channel when a signed development suite is available.
